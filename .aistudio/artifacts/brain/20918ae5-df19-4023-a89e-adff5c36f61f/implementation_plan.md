# 报表双周期对比视图与人员当期费用展示实现方案

本方案旨在为羽毛球群记账系统新增两大核心能力：在“报表”模块引入**双周期并排对比视图**（支持总费用、独立出勤人数、总出勤人次、两类人均成本差异对比），并在“人员”模块中**完整呈现成员在当前周期的费用金额**（包含集资人员名义包月金额同步，且保留原集资结算规则）。

---

## 用户确认决策与设计规范 (User Review & Critical Decisions)

> [!IMPORTANT]
> 根据 Phase 1 澄清问答，以下核心产品决策已确认并纳入本方案：

- **确认决策 1（报表展示形式）**：在报表顶部新增 Segmented Tabs 标签切换（【单周期报表】与【双周期对比】），保证操作平滑且不破坏原有单周期诊断与成员明细。
- **确认决策 2（人均成本双口径）**：对比视图中同时呈现两类人均成本指标：
  1. **独立出勤人均净支出** = 当期总费用 / 实际出勤独立人数（衡量每位参与球友的平均成本投入）。
  2. **场次均摊成本** = 当期总费用 / 总出勤人次（衡量每次打球人次的场地单价摊销）。
- **确认决策 3（人员费用展示）**：在人员模块中，在成员性质标签旁直接展示标准金额（如：`包月 ¥200`、`按次 ¥25`），彻底消除此前仅有 `¥` 符号或金额缺失的问题；集资人员同步体现标准包月金额（默认 ¥200），但后台保留集资人预付与返款的分摊结算逻辑不变。

## 1. 业务概述与核心概念 (Overview & Core Concept)

### 1.1 业务价值
1. **周期横向对比与趋势洞察**：组织者常需要对比连续两期（如 10 月 vs 11 月）的运营效能，通过总费用、出勤人数与人均成本的差异（Delta +/-），一眼掌握羽毛球群的活跃度变化与费用浮动趋势。
2. **人员当期标准清晰透明**：成员档案列表直接将当期的人员性质与应缴标准（包月/半月/按次金额）一体化展示，使组织者与成员对当期的计费基准一目了然。

### 1.2 目标用户
- 羽毛球群管理员与财务组织者：快速生成对比汇报、核对当期成员会费标准。
- 核心集资人与全体球友：清楚了解不同月份的群费用走向及人均性价比。

## 2. 用户体验与视觉设计 (User Experience & Visual Design)

### 2.1 交互流程走查

#### 流程一：双周期对比视图
1. 进入“报表”模块，顶部常驻轻量级切换控件：`[ 📊 单周期分析 ]` 与 `[ ⚖️ 双周期对比 ]`。
2. 切换至【双周期对比】：
   - 顶部呈现双周期选择行（基准周期 A 与 对比周期 B 下拉菜单，默认分别选择最新周期与上一周期）。
   - 核心指标对比面板（并排卡片或多列对比表格）：
     - **总费用**：周期 A 金额 vs 周期 B 金额（附差额 $\Delta$ 与百分比变化）。
     - **实际出勤独立人数**：A 期出勤总人数 vs B 期出勤总人数。
     - **总出勤人次**：A 期人次 vs B 期人次。
     - **人均成本（独立人数）**：A 期人均 vs B 期人均。
     - **场次人均成本（按人次）**：A 期人次均价 vs B 期人次均价。
     - **集资人结算指标**：每人预付投入对比、每人返款对比、人均盈余/超支对比。
   - 差异标注规范：增减数值以清爽徽标区分（费用降低标注为节省/绿色，费用上涨友好提示），适配手机屏宽自适应换行，避免截断。

#### 流程二：人员模块费用展示
1. 进入“人员”模块，成员卡片性质区域从原有的单一纯文本扩展为**性质 + 规范金额**。
2. 样式规范：
   - 普通包月：`[ 包月 ¥200 ]`（紫色高质感徽标）
   - 包半月：`[ 包半月 ¥100 ]`（天蓝色徽标）
   - 按次：`[ 按次 ¥25 ]`（翡翠绿色徽标）
   - 参与集资人员：保留当期集资专属金冠标识 `[ 👑 本期集资 ]`，性质标签显示为 `[ 包月 ¥200 ]`（或当期设定的包月金额），彻底解决人民币符号后无数字的问题。
3. 快捷切换性质按钮（包月/半月/按次）保持即时响应，切换后同步更新金额与当前周期配置。

## 3. 核心产品决策与技术权衡 (Key Product Decisions & Trade-Offs)

### 3.1 周期对比计算口径设计
- **计算逻辑**：
  - `总费用` = `courtCost`（基础场地支出）+ $\sum$ `sessionCost`（各场额外加支）。
  - `净收益/总结余` = 成员实付总额 - 总费用。
  - `独立出勤人数` = 周期内所有 Session 的 `attendees.playerId` 去重总和。
  - `总出勤人次` = 周期内所有 Session 的 `attendees.length` 累计总和。
  - `人均成本（独立人头）` = 总费用 / $\max(1, 独立出勤人数)$。
  - `人均成本（按人次）` = 总费用 / $\max(1, 总出勤人次)$。
- **降级与防空保护**：当任一周期无打球记录（0 人出勤）时，人均成本显示为 `¥0.00` 或 `--`，杜绝 `NaN` 或 `Infinity`。

### 3.2 人员模块中集资人员金额一致性
- **决策**：虽然集资人最终按 `(总投入 - 结余) / 集资人数` 进行期末清算，但在成员档案性质与常规缴费标准维度，集资人统一体现当期包月名义金额（默认 ¥200），符合“参与集资人员包月金额和普通包月人员一致，但是结算方式不改变”的要求。
- **实现**：在 `getPlayerPeriodConfig` 中增加兜底计算，如果成员为当期集资人员或包月人员且配置金额为空/0，自动继承该周期标准包月费用（或全局 `DEFAULT_MONTHLY_FEE`）。

               │                               │
               ▼                               ▼
┌──────────────────────────────┐ ┌──────────────────────────────┐
│       FinanceReport 模块     │ │       PlayersList 模块       │
├──────────────────────────────┤ ├──────────────────────────────┤

│                              │ │                              │
│ ┌─ PeriodCompareView ──────┐ │ │ 成员档案卡片:                │

│ │ ──────────────────────── │ │ │ - 性质与金额:                │

### 4.2 数据模型保证
无需更改持久化数据库字段结构，充分复用现有 TypeScript 类型：
- `Period`: `courtCost`, `sessions`, `funderIds`, `playerConfigs`
- `Player`: `defaultFee`, `type`, `isFunder`

### 4.3 实施关键步骤
1. **重构 `FinanceReport.tsx`**：
   - 增加视图模式状态 `reportTab: 'single' | 'compare'`。
   - 提取/新增双周期统计计算工具函数 `calculatePeriodComparison(periodA, periodB)`。
   - 构建高品质的 `PeriodCompareView` 组件，涵盖周期选择器、指标对比卡片网格、差额标签及手机端自适应布局。
2. **升级 `PlayersList.tsx`**：
   - 优化 `getPlayerPeriodConfig` 解析，集资人员与包月人员若无特殊单独设价，统一规范回退为本期包月金额。
   - 修正卡片中的费用渲染，将 `¥` 符号与数值一体化整合在性质标签或紧邻展示，确保数值清晰无遗漏。
3. **验证与构建**：
   - 执行 TypeScript 静态类型检查及 `compile_applet` 确保构建无错。
