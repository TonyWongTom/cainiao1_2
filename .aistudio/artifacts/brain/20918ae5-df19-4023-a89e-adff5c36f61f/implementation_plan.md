# 人员性质关联周期与录入记录双向同步实施方案

## 需求背景与目标
用户反馈：
1. **周期差异**：每个结算周期球友的性质（包月/包半月/按次）和包月费用各不相同，因此需要将“人员”中的性质与具体周期深度绑定。
2. **“人员”界面改造**：在“人员”页面顶部提供周期切换下拉选择器，默认选中当前最新周期。切换后展示、单人修改或批量修改均为对应周期的成员性质与费用。新建周期时所有成员性质默认初始化为“按次”。
3. **“录入记录”同步**：在“录入记录”的“第一步：选择出席成员”中，实时展现当期的人员性质；并允许直接调整成员性质（切换为包月时实收金额默认留空以便手动输入），该调整需双向实时同步更新至当期“人员”名单配置中。

## 总体技术方案与设计

### 1. 数据结构与辅助工具层 (`src/types.ts` & `src/utils`)
- `Period` 已包含 `playerConfigs?: PeriodPlayerConfig[]`，定义为 `{ playerId: string; type: PlayerType; fee: number }`。
- 提供统一的人员当期性质解析函数 `getPeriodPlayerConfig(period, playerId, player)`：
  - 若 `period.playerConfigs` 中存在对应项，以当期配置为准；
  - 若无当期配置，默认按次 (`PlayerType.PER_SESSION`) 并且默认单次费用采用标准次费（若新周期要求所有成员默认重置为按次）。
- 确保 `playerConfigs` 随 `Period` 变更保存时持久化到本地缓存和数据库。

### 2. “人员”页面按周期管理改造 (`src/components/PlayersList.tsx`)
- **顶部周期选择器**：
  - 顶部显式增加周期切换下拉框，默认自动选中最新/当前结算周期。
  - 选中对应周期后，列表展示各成员在**该周期下**的性质标签（包月、包半月、按次）及费用。
- **单人编辑与快捷修改**：
  - 点击编辑或快捷切换性质时，直接更新选中周期的 `playerConfigs`。
  - 同步更新全局 `periods` 状态，触发持久化存储。
- **批量改性质 (`handleBatchSave`)**：
  - 在当前所选周期范围内执行批量修改：勾选/识别出的成员设为目标性质与金额，未勾选的成员在当前周期内全部自动更新为“按次”，完美契合已有的批量逻辑并按周期隔离生效。
- **新建周期初始化**：
  - 在新建结算周期时，显式将 `playerConfigs` 初始化为全员“按次”（或为空并按默认“按次”解析），保障新老周期互不干扰。

### 3. “录入记录”第一步人员性质呈现与双向同步 (`src/components/PeriodsList.tsx`)
- **成员按钮与性质徽标**：
  - 在“第一步：选择出席成员”列表中，成员胶囊上清晰展示当期性质徽标（如 `包` / `半` / `次`）。
  - 支持在出席成员列表或选中标签上长按/点击性质标签切换（或在已选列表中快捷切换当期性质：包月 / 包半月 / 按次）。
- **实收金额设定逻辑（按澄清结果）**：
  - 当在录入记录中将成员性质切换为“包月”或“包半月”时，实收金额留空（空值），方便发起人根据当期实际收费手动填写。
  - 切换为“按次”时，自动恢复标准单场次费（¥30 或当期标准）。
- **双向数据同步**：
  - 当在录入步骤中修改某成员性质时，立即更新当前周期的 `playerConfigs`：
    ```ts
    // 同步更新当期配置
    setPeriods(prev => prev.map(p => {
      if (p.id !== periodId) return p;
      const nextConfigs = updatePlayerConfigInPeriod(p.playerConfigs, playerId, newType, newFee);
      return { ...p, playerConfigs: nextConfigs };
    }));
    ```
  - 这样当用户切换到“人员”栏目时，当期的人员性质已实时保持最新一致状态！

## 验证与测试步骤
1. **周期切换验证**：
   - 打开“人员”页面，验证顶部周期下拉框默认处于最新周期。
   - 切换到历史周期，确认展示的是历史周期的成员性质；切换回最新周期，显示当前周期的性质。
2. **批量与单人修改验证**：
   - 在“人员”页面执行“批量改性质”，确认仅影响当前所选周期，未选中的成员在当前周期均自动变为“按次”。
   - 查看另一周期，确认另一周期的成员性质未受任何波及。
3. **“录入记录”选择成员与性质联动验证**：
   - 进入“录入记录”，查看第一步出席成员的性质标签。
   - 在第一步中直接切换某成员性质为“包月”，确认金额留空以便手动输入。
   - 检查“人员”页面，确认当期该成员性质已经同步更新为“包月”。
4. **编译与代码质量检查**：
   - 运行 `lint_applet` 和 `compile_applet` 确保 0 报错，无类型冲突，正常运行。
