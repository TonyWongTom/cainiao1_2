# 财务报表上周期常客缺勤预警提示功能

在财务统计报表页面顶部新增「常客出勤异动与流失预警」面板。通过自动比对当前结算周期与上一结算周期的出勤数据，敏锐识别出“上周期经常出席（≥3次），但本周期缺席或鲜少出席（<2次）”的核心球友，提供出勤落差对比、人员性质展示以及一键复制关怀名单功能，帮助俱乐部管理员高效开展会员召回与温馨沟通。

## User Review & Critical Decisions

> [!IMPORTANT]
> 根据前序交互调研确认的明确偏好，本次功能实现将遵循以下关键设计规范与计算规则：

- **判定标准（已确认）**：球友在上一个结算周期内累计出勤 **≥ 3 次**，且在当前选中的结算周期内累计出勤 **< 2 次**（包含 0 次及 1 次）。
- **展示位置（已确认）**：仅在报表顶部以独立的专属预警提示卡片形式汇总展示，不干扰下方既有的人员详细结算表格。
- **辅助信息与快捷操作（已确认）**：
  - 显示球友姓名、人员性质（包月 / 按次 / 包半月）。
  - 展示出勤落差对照指标（如：`上期 5 次 ➔ 本期 0 次 (落差 -5)`）。
  - 提供「一键复制名单」与「一键复制微信关怀语」按钮，便于群发或私聊沟通。
- **稳定性承诺**：严格遵循既定价格计算公式、净结余返款逻辑、数据库与状态管理架构，零侵入无副作用。

## 1. Overview & Core Concept

- **解决的问题**：俱乐部管理员在结算周期结束或进行中时，难以直观发现哪些原本活跃的固定球友近期活跃度骤降，容易错失私聊关怀、询问球友近况或调整包月意向的最佳时机。
- **核心体验**：
  - 打开「财务报表」页面选择任意结算周期时，系统自动向前溯源该周期的「上一结算周期」。
  - 若检测到异常流失或低频出席人员，在报表顶部醒目呈现暖色系专属关怀卡片，标明缺席人数与各成员情况。
  - 支持折叠/展开、按出勤降幅排序，并可一键复制待关怀球友姓名或预设的礼貌关怀文案。
  - 若所有常客均正常出席或无常客断崖式减少，卡片展示安心绿色的「会员活跃度稳定」健康提示，也可一键轻量折叠收起。

## 2. User Experience & Visual Design

### 关键用户流程
1. **周期联动判定**：用户在报表顶部切换不同的结算周期，预警卡片即刻动态联动，取当前周期的前序周期进行基准对照。若当前周期为最早的周期（无上一周期），则提示“暂无历史周期对比数据”。
2. **直观数据卡片**：
   - 顶部标头：展示「常客活跃异动预警」标识、识别出的异动人数。
   - 快捷动作：右侧放置「复制名单」、「关怀模板」、「收起/展开」快捷按钮。
   - 人员网格/列表：每张球友小卡片显示球友姓名、性质标签（包月/包半月/按次）、上期出勤次数、本期出勤次数及差额。
3. **一键快捷复制**：
   - 点击「复制球友名单」：剪贴板写入 `李哥、王五、张三`，并伴有“已复制 3 位球友名单”即时 Toast 反馈。
   - 点击「复制关怀文案」：写入如：“Hi [球友]，最近俱乐部打球没怎么看到你，最近一切都好吗？这周有空一起打球呀～”。

### 视觉规范与反 AI Slop 纪律
- **色彩与层级**：采用温暖沉稳的琥珀橙/深暖灰双模配色（`amber-500/10` 柔和背景，`border-amber-200/40` 微细边框），既引起注意又避免过度的刺眼警告感。
- **排版与对齐**：所有出勤次数、百分比均应用 `tabular-nums font-mono`，防止数字对齐抖动；元数据采用自然文字和中圆点间隔（如 `包月 · 上期 6 次 · 本期 0 次`），杜绝厚重胶囊药丸堆叠。
- **单层阴影与整洁空间**：避免卡片套卡片（Cards within cards），采用干净的网格排布与极细边框（hairline divider）。

## 3. Key Product Decisions & Trade-Offs

- **周期对比基准策略**：
  - *方案*：以当前选中周期的按时间倒序排列的紧邻前一周期（`sortedPeriods[currentIndex + 1]`）作为对比基准，而非仅固定取最新的两个周期。
  - *原因*：当管理者回顾历史某月或某季度的财务报表时，依然能准确回溯当时相较于更早周期的会员留存状况，具备完全的历史可追溯性。
- **出勤口径**：
  - *方案*：统计各周期内所有 `sessions` 下已标记为该球友出席的记录总数（即 `playerBreakdown[playerId].count`）。
  - *原因*：完全复用财务报表中已有的 `playerBreakdown` 严谨统计口径，无需引入额外的临时查询逻辑，确保数据 100% 吻合。

### 核心状态与派生计算逻辑
```typescript
interface AttendanceDropOffPlayer {
  playerId: string;
  name: string;
  type: PlayerType;
  prevCount: number;
  currCount: number;
  diff: number; // prevCount - currCount
}

// 派生计算
const dropOffPlayers = useMemo(() => {
  if (!prevPeriod || !currentPeriod) return [];
  const prevStats = calculatePeriodStats(prevPeriod);
  const currStats = calculatePeriodStats(currentPeriod);
  
  return players
    .map(player => {
      const prevCount = prevStats.playerBreakdown[player.id]?.count || 0;
      const currCount = currStats.playerBreakdown[player.id]?.count || 0;
      return {
        playerId: player.id,
        name: player.name,
        type: player.type,
        prevCount,
        currCount,
        diff: prevCount - currCount
      };
    })
    .filter(item => item.prevCount >= 3 && item.currCount < 2)
    .sort((a, b) => b.diff - a.diff);
}, [players, prevPeriod, currentPeriod]);
```

## 5. Verification Plan

1. **多周期切换验证**：
   - 切换到不同周期，检查上一周期是否准确匹配并正确触发比较。
   - 选中历史最早的周期时，检查“无上一结算周期”友好说明。
2. **规则边界测试**：
   - 上周期出勤 3 次、本周期 0 次：触发提示。
   - 上周期出勤 4 次、本周期 1 次：触发提示。
   - 上周期出勤 3 次、本周期 2 次：不触发（出勤已达 2 次）。
   - 上周期出勤 2 次、本周期 0 次：不触发（上周期未达到 3 次常来标准）。
3. **快捷交互验证**：
   - 点击“复制名单”并粘贴，验证名单内容无误并触发轻量级提示。
   - 点击“复制关怀文案”，验证文案包含姓名并格式友好。
   - 点击展开/收起，验证界面空间舒适自如。
4. **代码质检**：
   - 运行 `compile_applet` 和 `lint_applet` 确保构建与语法 100% 通过。
